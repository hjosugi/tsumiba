# トラブルシューティングと FAQ {#troubleshooting-and-faq}

まず、報告や修正をしやすくする 2 つのこと:

```sh
tsumiba paths                    # 設定・データ・ログの場所
TSUMIBA_LOG=debug tsumiba        # ターミナルで、詳細なログを出して実行
```

**ログファイル**は、データフォルダーの `tsumiba.log` です(`tsumiba paths` で表示。ひとつ前のものは
`tsumiba.log.old`)。起動時の問題は、出力先のコンソールが無い Windows でも、ここに記録されます。

## 起動 {#starting}

### 起動しても何も現れない {#nothing-appears}

tsumiba を起動すると積み場が開くので、何も開かないときは、ターミナルの出力(ターミナルから `tsumiba` を
実行してください)とログを見てください。よくある原因:

- **システムライブラリが足りない**(Linux)。tsumiba は起動時に、OpenGL、`libxkbcommon`、X11 キーボード
  ライブラリの `libxkbcommon-x11`(X11 セッション)、X11 または Wayland のライブラリを読み込み、足りない
  ものを伝えます。一番多いのは「X11 のキーボードライブラリが必要です」というメッセージで、
  `libxkbcommon-x11-0`(Debian、Ubuntu)または `libxkbcommon-x11`(Fedora、Arch)をインストールして
  ください。[Linux の動作要件](installation.md#linux-requirements)を参照。
- **「ウィンドウを作成できませんでした」**と OpenGL のメッセージ。tsumiba には OpenGL 2.0 以降が必要です
  (3.x が望ましい)。GPU ドライバーの無い Linux マシンでは、`LIBGL_ALWAYS_SOFTWARE=1` で Mesa の
  ソフトウェアレンダラーが使えます。Windows については、下の[ウィンドウを作成できない場合](#windows-opengl)を
  参照してください。
- **すでに起動している。**2 回目の起動は、起動中のものに表示を頼みます。積み場が現れないときは、
  `tsumiba toggle` を試すか、`tsumiba quit` で終了してからもう一度起動してください。

### 「ポート 47821 は使用中」と表示された {#port-taken}

別のプログラムがそのポートを握っています。tsumiba は空きポートを選んで通知します。コマンドラインは自分で
見つけます。**ブラウザ拡張**には、オプションに新しいポートを入れる必要があります(新しい番号は
**設定 → ブラウザ拡張**に表示されます)。避けるには、`api.port` を空いているポートにするか、常にシステムに
選ばせる `0` にしてください。

## 呼び出し {#summoning}

### ブラウザのタブに手を伸ばしただけで開いてしまう {#edge-opens-by-accident}

画面上部のタブバーにポインターを少し置いただけで、呼び出しのように見えてしまうことがあります。トリガーは
すでに慎重になっています(上端の**中央付近だけ**、パネルと同じ幅、**250 ms** の静止)。次の対処ができます。

- 待ち時間を延ばす:**設定 → 呼び出し → 待ち時間**、または `trigger.edge_dwell_ms = 500`
- パネルを狭くして、有効な範囲を小さくする
- 上端をオフにして(`trigger.edge = false`)、ショートカットだけを使う

なお、**ドラッグ**中は設計上、待ち時間がないので、何かを画面の一番上でドラッグすると開くことがあります。

### 上端のトリガーが何も起こさない {#edge-does-nothing}

- **Wayland** には上端トリガーがありません([積み場を呼び出す](summoning.md#wayland))。
- オンになっていますか?**設定 → 呼び出し → 画面上端で表示**。
- ポインターは、画面の一番上の段の、中央付近にある必要があります。モニターが 2 台あれば、それぞれに上端が
  あります。モニターを縦に積んでいる場合、ポインターは下のモニターの最上段で止まらず、境界をそのまま
  通り抜けます。
- macOS では積み場はメニューバーのすぐ下に開きますが、トリガーは本当の最上端です。

### ショートカットが効かない、または設定で「使えない」と表示される {#shortcut-does-nothing}

- **Wayland** ではグローバルショートカットは使えません。デスクトップのキーボード設定で
  `tsumiba toggle` を割り当ててください([コマンドライン](cli.md#examples))。
- ほかのプログラムが、すでに <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>Space</kbd> を使っているかもしれません。
  設定しようとすると tsumiba がそう伝え、元のショートカットを維持します。別の組み合わせを選んでください。
- 入力メソッドの切り替えが同じキーを使うことがあります。<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Space</kbd> や
  ファンクションキーを試してください。

### トレイアイコンが出ない {#no-tray-icon}

- **GNOME** は、*AppIndicator and KStatusNotifierItem Support* 拡張が無いとステータスアイコンを表示
  しません。ステータス通知トレイのあるほかのデスクトップは、そのまま使えます。
- 積み場には、ショートカット、上端、`tsumiba toggle` から引き続き到達できます。

### 開くけれど、入力が反映されない {#no-keyboard-focus}

積み場はほかと同じウィンドウで、入力を受けるにはキーボードフォーカスが必要です。オペレーティング
システムは、キーを押したからではなく*ポインター*が上端に触れたから現れたウィンドウに、フォーカスを
渡すことを拒むことがあります。積み場の中を一度クリックしてください。毎回そうなるなら、ショートカット
で呼び出してください。(実際の Windows や macOS のマシンでは再現を確認していません。)

## 文字と見た目 {#text-and-appearance}

### 日本語が空の四角で表示される {#japanese-boxes}

tsumiba は日本語フォントを持っていません。起動時に、システムにすでにあるフォントを探します(macOS では
ヒラギノ角ゴ、Windows では Yu Gothic UI や Meiryo、Linux では Noto Sans CJK JP や IPAexGothic など)。
そのフォントに本当に文字が含まれているかを確認し、フォールバックとして使います。この処理は
バックグラウンドで行われるので、最初の少しの間は四角が出ることがあります。ずっと残る場合は、適切な
フォントが見つからなかったということなので、インストールして(Debian や Ubuntu なら `fonts-noto-cjk`)
再起動してください。ログには、どのフォントを使ったか(`using … for Japanese text`)、または見つからなかった
ことが記録されます。

### 日本語が入力できない {#japanese-input}

入力メソッドはウィンドウシステムを通じて働きます。変換が表示されないときは、入力メソッドが起動して
いて、X11 や Wayland のアプリケーションに対応していることを確認してください。あらゆる IME での動作は
確認していません。

### 小さすぎる、大きすぎる、別のモニターに出る {#size-and-monitor}

**設定 → パネル**(即時反映)、または `panel.width` と `panel.height` でサイズを変えられます。ポインターの
あるモニターに開きます。スケールの異なる画面では、配置はベストエフォートです。

## ファイルとメモ {#files-and-notes}

### タイルに「見つかりません」と表示される {#tile-missing}

そのファイルは**リンク**として追加され、元のファイルがその後移動または削除されました。タイルを外すか、
ファイルを元の場所に戻してください。リンクはファイルをコピーしません。[ファイル](files.md#copy-or-link)を
参照。

### 何かを削除してしまった {#deleted-something}

6 秒以内なら、画面下のメッセージの**元に戻す**を使ってください。それ以降も、ゴミ箱フォルダーに 30 日間
残っています([データと同期](data-and-sync.md#the-trash))。

### 同期したらメモが消えた {#sync-lost-notes}

`notes/` に競合コピーが無いか確認し、[同期](data-and-sync.md#syncing)を読んでください。`index.json` が
壊れていた場合、積み場はそれを再構築しますが、失われるのはピン留め・取得元・リンクだけです。

### ブラウザからファイルをアップロードできない:「大きすぎる」 {#upload-too-large}

API の上限は `storage.max_upload_mb` で、既定は 512 MiB です。

## オペレーティングシステム {#operating-systems}

### Windows:「Windows によって PC が保護されました」 {#smartscreen}

プログラムがまだコード署名されていないため、SmartScreen が認識しません。**詳細情報**を選び、**実行**を
押してください。先に、ダウンロードを `SHA256SUMS.txt` と照合して確認することもできます。

### Windows:ウィンドウを作成できない(仮想マシン、リモートデスクトップ) {#windows-opengl}

グラフィックドライバーの無い Windows マシン(多くの仮想マシンや、一部のリモートデスクトップのセッション)には、
Windows 組み込みの OpenGL 1.1 のスタブしかなく、tsumiba の既定のレンダラーはそれを使えません。ログには
`egui_glow requires opengl 2.0+` のような文言が出ます。Windows では、tsumiba が自分でこれに対処します。
既定の設定(`general.renderer = "auto"`)では、OpenGL でウィンドウを作れなかった場合に、**一度だけ wgpu レンダラー
(DirectX 12。フォールバックとして Microsoft のソフトウェアラスタライザー WARP)で自分自身を再起動**します。
何もする必要はありませんが、起動の試行が 1 回増えるので、少し時間がかかります。

明示的に選ぶには、`config.toml` の `general.renderer` を `"wgpu"`(または `"glow"`)にするか、環境変数
`TSUMIBA_RENDERER`(`wgpu`・`glow`・`auto`)を設定してください。環境変数のほうがファイルより優先されます。
Linux と macOS のビルドには OpenGL しか含まれていません。

> [!NOTE]
> このフォールバックを実際に動かしているのは、CI の GPU の無い Windows ランナー(参考扱いのジョブ)だけで、
> 実際の仮想マシンでは作者は試していません。うまくいかない場合は、ログファイルを添えて
> [報告](https://github.com/hjosugi/tsumiba/issues)してください。

### macOS:「Tsumiba は壊れています」または「開けません」 {#gatekeeper}

アプリは ad-hoc 署名のみで公証されていないため、隔離属性がブロックします。右クリック →**開く**、または:

```sh
xattr -dr com.apple.quarantine /Applications/Tsumiba.app
```

### Linux:X11 では動くが Wayland では動かない(またはその逆) {#x11-wayland}

Wayland では、積み場は上端トリガーもショートカットも無い通常のウィンドウです。Wayland のデスクトップで
X11 の挙動がほしい場合、`WINIT_UNIX_BACKEND=x11 tsumiba` で XWayland 経由で動かせます(未試験で、ポインターと
キーは X11 ウィンドウの上にある間しか見えません)。

## FAQ {#faq}

**なぜクリップボード履歴が無いのですか?**範囲を絞っているからです。Unclutter にはありますし、クリップボード
履歴をうまく扱うツールはたくさんあります。tsumiba はメモとファイルを扱い、それをうまくやることを目指します。

**なぜファイルを外へドラッグできないのですか?**ウィンドウツールキットがネイティブのドラッグを開始できない
からです。理由と代替手段は[ファイル](files.md#dragging-files-out)を参照してください。

**コンピューター間で同期されますか?**組み込みの同期はありません。データは普通のファイルなので、どんな
ファイル同期ツールでも使えます([データと同期](data-and-sync.md#syncing))。

**USB メモリから動かせますか?**はい。起動する前に `TSUMIBA_HOME` をメモリ上のフォルダーに設定して
ください。ほかには何も書き込まれません(ログイン項目を頼んだ場合を除く)。

**外部に通信したり、更新を確認したりしますか?**いいえ([プライバシーとセキュリティ](privacy-and-security.md))。

**積み場を 2 つ動かせますか?**はい、`TSUMIBA_HOME` を別の値にすれば動かせます。フォルダーは別になり、
(両方が動くなら)ポートも別にする必要があります。`api.port` を変えるか、`0` にしてください。
